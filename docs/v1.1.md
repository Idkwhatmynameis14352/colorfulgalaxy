# v1.1 development notes — 2026-11-08

## Baseline and backup
Owner confirmed v1 boots. The exact v1 package and adapted boot image remain in the private local versions/v1 snapshot. Original recovery/radio/identity and relocation backups remain private. Targeted OTA files, package state and keyboard settings were saved before modifying them. This is not a user-data backup.

## Retained changes
1. Disable com.oplus.ota, com.oplus.sau and com.oplus.sauhelper for user 0 and force-stop them.
2. Reversibly rename the three updater APKs, cotad, bspFwUpdate and cotad.rc to .disabled-v1.1 suffixes. Original contents and metadata are retained in place. Stop cotad/cotad-boot and return the system filesystem to read-only. This prevents normal package discovery and native daemon startup on this build. A later ROM reflash can restore them, so the block must be carried into future builds. This is not a guarantee against a user deliberately flashing a different ROM in recovery.
3. Restore the missing user-0 input-method selection to the already installed Sogou IME. Keep OPPO's separate security keyboard installed. The repair script does nothing when a keyboard is already selected.
4. Compile only the original Oplus launcher with ART's speed filter. No APK code/resources, animation scales, graphics flags, frequency limits, thermal protections, or memory parameters are changed.

## Experiments and evidence
- Settings was only in verify state. A targeted speed compilation produced inconsistent results across two samples; it was reverted to verify. No Settings performance improvement is claimed.
- Launcher was in verify state. In one fixed four-cycle Settings/home sequence, reported frame deadline misses fell from 20/262 (7.63%) to 19/364 (5.22%). Median reported frame time: 44 -> 40 ms; p90: 97 -> 69 ms. This remains visibly above a 60 Hz frame budget. Different frame counts, warm caches, thermal state and vendor frame-accounting limit the comparison. It is an initial signal, not proof of daily smoothness.
- Keyboard appeared in 3/3 Settings-search tests after restoring selection. Intermittent behavior still needs testing across apps and password fields.
- SurfaceFlinger loads vendor libGLES_mali.so; app rendering reports Skia/OpenGL; HWC 2.4 and gralloc are running; captured layers use DEVICE composition. GPU is Mali-G71 and DVFS uses its Interactive governor. Software-rendering-sounding properties were not changed based only on their names.
- CPU clusters use Interactive governors. Normal thermal status and active thermal HAL observed. Existing frequency limits were not raised. No thermal protections were disabled.
- About 1 GiB MemAvailable in the sampled workload. A short vmstat sample showed no swap-in/out or I/O wait. No justification found for changing LMK, zram or swappiness.
- No unrelated OPPO services removed. Baseline boot crash history includes unrelated vendor/IMS errors; these are not treated as permission to remove telephony components.

## Validation and remaining work
Reboot passed. OTA packages are absent from package discovery, cotad has no loaded init service, keyboard selection persists and the keyboard appeared again in Settings search. SurfaceFlinger/HWC are running and SELinux is enforcing. No updater jobs were found in the post-reboot scheduler dump. Camera service enumerates both cameras and audio HAL initializes; actual photo/video/audio playback remain owner tests. Reboot validation is recorded in the private local session report. Wi-Fi, rendering and keyboard persistence are checked without changing their drivers. No SIM is inserted, so calls/mobile data cannot be validated. Camera, audio, touchscreen edge cases, suspend, charging and long-session stability still require owner testing. Keep the original ColorOS appearance and animations.

No official OPPO OTA package has been downloaded or flashed. No full ROM reflash or data wipe was used for v1.1. Scripts here apply runtime changes to the already-installed development build; they are not a universal recovery-flashable ROM.
